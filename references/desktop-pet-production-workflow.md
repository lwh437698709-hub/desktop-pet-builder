# 桌面宠物制作标准流程

这份流程以灰白猫桌宠的最终预览和 Windows 安装包为基线，适用于把角色图片、动作视频和输入事件整理成可运行的桌面宠物。目标是先把素材做对、确认后再接入程序；用程序处理输入、播放与状态切换，用动画素材表现猫本身的姿势变化。

## 必须确认的两个节点

1. **动作选择 → 提供对应图片 → 生成提示词**：动作需求不明确时，先请用户选择要做的动作；选定后，再收集角色身份基准图和对应动作姿态图。已有附件可直接使用，不重复索要。图片齐全后，按所选动作生成保留角色外观、镜头、背景、连续性和起止姿势要求的提示词。
2. **打包平台选择**：只做素材或提示词时不必问平台。进入程序接入或打包前，如果上下文未明确目标平台，再请用户选择 macOS、Windows 或两者；不根据当前开发电脑推断目标平台。

素材序列抠图完成、整段预览通过后，先交用户确认，再替换桌宠中的正式资源。

## 1. 先定义验收目标

开始制作前先写一页动作规格，记录：

- **角色基准**：唯一外形参考、毛色/斑纹/眼睛/体型、不可改变的特征。
- **动作表**：触发事件、进入状态、循环或单次播放、结束姿势、回到哪个状态。
- **显示规格**：窗口尺寸、透明背景、基准头部宽度、脚底/头部锚点、缩放选项。
- **平台规格**：macOS/Windows 版本、全局鼠标/键盘监听方式、首次授权和自动启动要求。
- **交付清单**：原始视频、提示词、关键帧、透明帧、图集、程序、安装包及验收记录。

建议把状态关系画成简单表格，不要让程序和视频各自猜测动作逻辑。当前猫咪的状态约定可参考 [Windows 版说明](cat-desktop-pet-windows/README.md) 和 [帧定位记录](cat-desktop-pet-mac-preview/Assets/cat-motion-keyframes.json)。

## 2. 固定角色与素材规格

1. 保存未修改的角色正面图和每段原始视频；不覆盖源文件。
2. 用正面全身图做身份基准，其他姿势图只定义姿势，不覆盖角色外形标准。
3. 收到视频先记录分辨率、帧率、时长、画幅和背景。优先用最高分辨率母版抽帧；不要把预览缩略图当母版。
4. 固定一个透明帧画布与锚点。当前项目使用 **1200×1540** 画布；新角色可以选别的尺寸，但同一个桌宠的所有动作必须一致。
5. 先生成或处理一个短 Pilot，检查清晰度、绿幕/透明边缘、动作方向和角色一致性，通过后再批量处理，避免把错误放大到整段素材。

## 3. 抽关键帧并确认动作

每个动作先确定清楚的开始态、主要动作、结束态。例如：

| 状态 | 触发 | 播放方式 | 结束/返回 |
|---|---|---|---|
| 待机看鼠标 | 空闲时鼠标移动 | 按方向选帧 | 鼠标停止时停在当前方向 |
| 被提起摇摆 | 按住猫咪并拖动 | 摇摆素材循环 | 松开后进入落地 |
| 落地 | 松开鼠标 | 单次播放 | 用姿势匹配的末帧回待机 |
| 踩奶 | 键盘按下/持续按住 | 输入期间循环；速度可随输入节奏变 | 松键一段时间后淡回待机 |

用原始视频按原生帧率或明确的采样策略导出帧，制作**编号接触表**，同时提供关键帧大图和连续播放预览。接触表用于找到异常帧，连续预览用于发现闪动、抖动和不连贯；两种检查不能互相替代。涉及新动作素材时，关键帧和抠图结果先给用户审看，确认后再替换已运行版本。

若视频不包含完整视角，不要把插值帧描述成真实拍到的 360° 视角。插值只能补足播放采样，仍需检查闭环接缝和伪影；严重变形帧应剔除、用原片替换或重新生成，不要为了凑帧数保留坏帧。

## 4. 抠图与逐帧修复

1. 记录抽帧编号、来源时间码、抠图参数和输出尺寸，让问题可以回到原片重做。
2. 对绿幕素材用统一色键/分割参数处理整段，再检查毛发边缘、胡须、爪缝、键盘字样和半透明边缘；不能为了“扣干净”不断放宽阈值，导致主体破损或背景漏边。
3. 若问题集中在固定一侧，先定义一条**稳定的边界曲线/遮罩规则**，只修问题帧并对比相邻帧。不要逐帧随意画不同边界，也不要不断扩大抠除区域。
4. 每帧检查猫耳、身体轮廓、四爪、尾巴、道具边缘是否完整；边缘缺损、残影、黑块、透明洞、绿边和突然变化都标记为异常。
5. 先做整段缩略接触表筛查，再把所有可疑帧放大检查；播放原尺寸动画，确认修复没有引入新闪烁。帧号列表、修复方式和前后对照一起留档。

## 5. 统一大小与转场

- 所有动作放到同样大小的透明画布，使用相同的角色头部宽度作为标尺，并记录头部中心/眼线、头顶和脚底锚点。
- **只做等比例缩放和位置平移**，不分别拉伸宽高；不能用压扁或拉长来让红框“看起来对齐”。
- 不同动作要分别对齐头部尺度和动作锚点。例如被提起时鼠标落在头部锚点；落地后末帧与待机的头部位置重叠。
- 转场末帧优先从素材中找姿势最接近目标状态的真实帧。用它作为落地终态，再核对头部大小、方向、坐标和尾巴完整性。
- 待机末帧与落地终态允许有经过确认的轻微尺寸差异；数值和原因写进定位记录，不能靠运行时突然缩放来掩盖素材不匹配。
- 所有帧在画布边缘留透明安全区，尤其检查尾巴、耳尖、胡须和落地时向外伸展的爪子。

## 6. 接入程序：用状态机驱动

把素材动作和程序控制分开：视频/帧序列决定猫如何动，程序决定何时进入、循环、结束和转场。每个时刻只显示一个有效动画状态，避免新旧图层叠加造成“影像重叠”。

- 待机方向选择应是确定映射；方向闭环首尾相邻，鼠标停止时帧不漂移。
- 按住拖动期间保持一个循环动作，左拖与右拖是否镜像按规格决定，不临时翻转素材。
- 松开事件只触发一次落地播放；落地期间不再被鼠标位置打断，结束后先固定正视，等下一次鼠标移动再恢复跟随。
- 键盘监控应使用明确的按下/松开事件语义：区分按住、快速敲击、自动重复和最后一个键释放；只使用事件时序控制动作，不读取或保存键入字符。
- 监控状态需要可诊断：菜单或日志能区分“已安装监听器”“收到按键”“当前动作”。权限/辅助功能授权要在 macOS 更新应用后复查；固定签名身份，避免每次重编译都换授权对象。
- 大小设置用等比例缩放，选项和当前状态可见并持久保存；切换大小时维持合适锚点，不让猫突然跳位。

## 7. 打包、升级和自动启动

Windows MSI 的每次发布都要同步程序版本和 MSI 版本，并生成新 ProductCode；稳定保留 UpgradeCode。升级规则需覆盖所有旧版本，安排在安装新文件前移除旧产品，安装目录维持固定。不要仅凭成功生成 MSI 就认为升级链有效。

- EXE、开始菜单快捷方式、卸载程序图标使用同一套猫咪头像资源；安装包里核对图标资源确实存在。
- 快捷方式和自动启动入口使用 MSI 文件引用（文件 ID），不要拼错或硬编码旧安装路径；登录启动项要可在卸载时清除。
- 自包含发布适合用户无需另装运行时的场景；按目标架构打包，例如 x64。
- 最终包在真实 Windows 10 和 11 上分别做全新安装、覆盖升级、启动、键盘监控、右键大小切换、登录自启和卸载检查。还要验证开始菜单快捷方式与实际安装路径一致。
- 没有可信证书时如实标记为未签名；签名应覆盖应用二进制和 MSI，并在签名后验证。

## 8. 发布前验收清单

- [ ] 身份特征与基准图一致；动作开始、循环、结束状态明确。
- [ ] 所有帧在原尺寸连续播放检查，无坏帧、抠图闪动、图层重叠或尾巴/爪子裁切。
- [ ] 各状态头部大小和锚点一致；无非等比缩放。
- [ ] 过渡至少逐帧看一遍接缝：待机→拖拽、拖拽→落地、落地→待机、待机→踩奶、踩奶→待机。
- [ ] 鼠标与键盘输入只触发预定状态；快速输入、长按、松开和连续切换均自然。
- [ ] 小尺寸下边缘清晰、不卡顿；素材内存和加载时间符合目标设备。
- [ ] MSI 中的版本、产品代码、安装路径、升级范围、快捷方式目标、图标和自动启动项均已核对。
- [ ] Windows 10、Windows 11 实机安装与覆盖升级成功；卸载干净移除文件和启动项。
- [ ] 用户确认最终素材和预览后才做正式替换/发布；交付包附版本号和修改记录。

## 本项目的已验证基准

- 统一透明画布：1200×1540；所有状态等比例缩放，不压扁、不拉长。
- 待机：4K 来源、闭环方向帧；少量明显失真的眼部帧剔除后再均匀映射。
- 拖拽摇摆：97 帧，24fps 循环；左右共享一个动作。
- 落地：从 4K 原片重新提取，选择与待机相近的坐姿终态；约 3 倍播放速度，并专门复查尾巴帧。
- 踩奶：121 帧；修复范围需逐帧核验左侧轮廓、Enter/Space 键边缘和爪子，不因问题扩大抠图区域。
- Windows 安装：x64，自包含 MSI；安装升级保持同一程序路径，包含头像图标、用户登录启动项和记忆尺寸设置。

数字仅是当前猫咪素材的已验证参数；新角色和新视频要重新测量、抽帧、对齐和验收，不应机械照搬。
